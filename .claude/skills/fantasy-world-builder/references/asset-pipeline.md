# 資產流程：取得、整理、最佳化、登記

## 0. 先查資產庫

`assets/library.json` 是唯一的清單。每個資產一筆，不論來源、不論這次有沒有用上。
先問：現有的能不能直接用？換個配色（`mats`）？縮放或倒掛？兩三個組合成新的東西？
能的話就不要生成新的。

## 1. 決定來源

| 需求 | 來源 |
|---|---|
| 幾何規則、需要和軌道同一種上漆木頭質感（欄杆、橋、塔身、齒輪、平台） | Blender 腳本（路徑 A） |
| 英雄級地標、有機形體、雕像、繁複的建築、特殊植物 | Meshy（路徑 B） |
| 大量重複的小東西 | 一個做好的資產加實例化，不要每個都生成 |

## 2. Meshy：成本閘門

每次扣點前都要走完這四步，缺一不可：

1. 列出要生成的項目，每項一句話說明它在場景裡的角色，以及為什麼現有資產不夠用。
2. 估算成本。只用 Meshy Skill 認可的兩種來源：`meshy make "…" --dry-run` 的規劃結果，或官方價目表。講明用的是哪一種。
3. 報目前餘額：`meshy balance --format json --no-update-check`。
4. 等使用者明確同意。同意的範圍就是你列出的項目；想多做一個變體、重跑一次、加一個階段，都要再問。

生成結束後把 `consumed_credits` 記進該資產的 `meshy.credits`，並累加到清單頂層的 `meshyCreditsSpent`。
結果不滿意時，先試不花錢的辦法（在 Blender 修、重新上色、換用途），再考慮重跑。

## 3. Meshy：本專案的做法

實際操作一律交給 `meshy-3d-generation` Skill（登入、指令、等待、下載、錯誤處理都在那裡）。這裡只補充專案相關的判斷：

- **用途要先講明**：這是網頁遊戲的場景資產，有面數預算。所以選 Smart Topology 並設定目標面數，而不是生成高模再砍。
- **建議走「先出參考圖、使用者點頭、再轉 3D」**。一張圖比一段文字更能控制風格，也避免為了風格不對而重付一次模型的錢。
- **風格描述的方向**（不是固定咒語，依資產調整）：手作微縮模型、上漆的木頭或陶土、乾淨可辨的大形、柔和霧面、童話比例、單一物件、完整可見、中性背景。
  需要和現有世界一致時，直接把現有畫面的截圖當作風格參考。
- **避免**：寫實掃描感、髒污破舊、細碎到在遊戲距離看不見的細節、底座或地面一起生成、多個物件黏在一起。
- **一個任務一個物件**。整個場景、地面、要拆開組裝的東西都不適合用生成。
- 原始下載檔放 `assets/source/<id>/`，連同提示語、參考圖、任務 ID 一起留著，之後才能重新貼圖或 remesh 而不必重新生成。

### 實測紀錄（2026-11-12）

- `text-to-3d` 標準模型：預覽 20 點、貼圖（refine，2k）10 點，一個資產共 30 點。
- 下載的 GLB 是 110 到 245 MB、350 萬到 800 萬三角形。Blender 減面到 1.4 萬／1.8 萬後觀感仍然很好，檔案 0.9／1.4 MB。
- 減面一個 800 萬面的模型約需 100 秒；Blender MCP 在這段時間不會回應，屬正常。
- 下次可以考慮改用 Smart Topology 直接指定面數，省掉減面這一步（價格要另外查價目表）。
- 使用者已同意貼圖階段可以自行送出；新的幾何生成仍然要先報價。

## 4. 在 Blender 整理

用 Blender MCP。在獨立的場景裡做（目前慣例：道具用 `Plexulisa`、房間用 `PlexulisaRoom`；匯入的資產另開 `PlexulisaAssets`），不要動使用者場景裡的其他東西。

1. 匯入後先看：`get_scene_info` 讀尺寸與面數，`look` 從多個角度看。
2. **方向與原點**：Z 向上，正面朝 `-Y`，原點在底部中心（會倒掛或側立的也一樣，以「站立面」為底）。
3. **尺度**：依 [project-contract.md](project-contract.md) 的尺度表縮放到遊戲單位並套用變換。和鋼珠（直徑 0.36）擺在一起看比例。
4. **清理**：刪掉生成時附帶的底座、浮在空中的碎片、內部看不見的面；修正法線。
5. **面數**：超過預算就減面，但要看著剪影減，輪廓壞掉就停。
6. **貼圖**：縮到預算內的解析度；烘進貼圖的打光太重時要壓掉，因為遊戲有自己的光。
7. **風格校正**：粗糙度、飽和度、明度調到和周圍資產一致。
8. **碰撞代理**：另做一個簡化網格（包住主要形體即可），匯出成遊戲座標的三角形資料。
   `tools/blender_props.py` 的 `export_collision()` 是現成的寫法。
9. **匯出**：GLB，套用修改器，Y 向上。路徑 A 併入 `public/props.glb`；路徑 B 存成 `public/assets/<id>.glb`。
10. **預覽圖**：存到 `assets/previews/<id>.png`。

## 5. 網頁效能預算

這些是起點，不是硬規定；超出時要說明理由並看實際幀率。

| 類別 | 三角形 | 貼圖 |
|---|---|---|
| 英雄地標（每區一個） | 8k – 20k | 一張 1024 – 2048 |
| 中型建築、大型植物 | 2k – 6k | 一張 512 – 1024 |
| 重複的小道具（要實例化） | 200 – 1.2k | 512 以下，或共用圖集 |
| 碰撞代理 | 渲染網格的 5 – 15%，單一資產不超過約 1.5k | — |

整體參考線（桌機目標 60 fps 以上，手機要還能玩）：

- 球內場景總三角形 40 萬以內；目前道具加軌道遠低於此。
- 首次載入的資產總量 25 MB 以內；單一 GLB 盡量 3 MB 以內。
- 貼圖總量約等於 8 張 2048 以內。能用頂點色或具名材質解決的就不要貼圖。
- 繪製呼叫：同一資產多次出現就實例化；路徑 A 的道具會自動依材質合併。
- 物理碰撞三角形目前約 14 萬，新增景觀後盡量不超過 25 萬。

檢查工具：

```bash
node scripts/asset-report.mjs public/props.glb public/room.glb public/assets/*.glb
```

需要壓縮（Draco／Meshopt、貼圖轉 WebP）時可以用 `npx @gltf-transform/cli`。它不在專案依賴裡，第一次使用會下載套件，先跟使用者說一聲；
用了壓縮格式，`render.js` 的載入器也要掛上對應的解碼器。

## 6. 登記到資產庫

`assets/library.json` 每筆的欄位：

| 欄位 | 說明 |
|---|---|
| `id` | 唯一名稱，也是 `prop()` 用的名字 |
| `kind` | `landmark`、`architecture`、`flora`、`prop`、`mechanism`、`creature`、`terrain`、`environment` |
| `status` | `in-game`（已在場景中）、`ready`（整理好、可直接用）、`draft`（原始檔或半成品） |
| `origin` | `blender-script`、`meshy`、`hand-modelled`… |
| `path` | `A`（具名材質）、`B`（貼圖資產）、`room` |
| `file`、`source` | 遊戲用的檔案；原始檔或產生它的腳本 |
| `tris`、`drawPrims`、`textures`、`size` | 由 `asset-report.mjs` 讀出來，不要用猜的 |
| `pivot`、`collision` | 原點慣例；碰撞用完整網格、代理或沒有 |
| `materials`、`tags` | 材質名稱；找資產用的標籤（區域、主題、用途） |
| `meshy` | 僅 Meshy 資產：`taskId`、`prompt`、`model`、`credits`、`date` |
| `preview`、`notes` | 預覽圖路徑；已知問題、可以怎麼再利用 |

資產從場景拿掉時改回 `ready`，不要刪掉紀錄。
