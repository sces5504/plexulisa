# 每顆球的驗收標準

這個遊戲會有很多顆不同的球。每一顆（新做的或改過的）在交付前都要過這份清單。
這些標準來自使用者的實際要求，不是泛泛的建議。

## 一顆球要達到什麼

**從外面看，是一顆很漂亮、很複雜、塞得滿滿的微縮奇幻 Snow Globe，讓人想進去一探究竟。
進到裡面，是一座 Perplexus 等級的立體遊樂場，鋼珠有很多條不同的路可以走，像不同的關卡。**

兩件事同時成立才算完成。只有景沒有路是擺飾；只有路沒有景是教具。

使用者明確退回過的做法：**太工整、太公式化**。下面這些都算：

- 站台放在六個極點或正好對稱的位置；路線沿著大圓走。
- 每一站都是「圓台＋底下一顆浮島＋旁邊幾個道具」。
- 所有路都在同一個高度帶、同一個朝上方向。
- 景觀是軌道排完之後才填進空位的。
- 球裡有一大塊沒東西的空間（上半球、底部、背面、正中央）。

## 製作順序：先做一顆好看的球，再把軌道放進去

**順序不能反過來。** 每一步做完都要實際看畫面（球外三個角度以上），不滿意就回頭改，不要帶著不好看的骨架往下做。

1. **故事與一句話**：這顆球裡發生什麼事？誰住在這裡、鋼珠是來做什麼的？寫成三五句話給使用者看。
   故事決定地標、決定路線為什麼往那裡去、決定每一段路的皮膚和機關。
2. **剪影**：從球外看的大形。決定兩三個大塊體量（一座山、一棵巨樹、一艘倒掛的船、一圈城牆……）怎麼佔滿整顆球：
   哪裡頂到玻璃、哪裡從上面垂下來、哪裡橫跨中央、哪裡刻意留一個看得穿的洞。
   **體量不對稱、不居中、不同高。** 這一步只用大塊的形（可以是佔位幾何，要標明是草稿），先看輪廓。
3. **把景做出來**：地形、建築、植物、會發光的東西。這時還沒有軌道。
   做到「就算不能玩，放在桌上也是一顆想買的 Snow Globe」的程度，再往下。
   大型地形與英雄地標放在這顆球自己的資料夾（`src/globes/<id>/`）；可重複使用的東西進共用庫。
4. **找路**：看著做好的景問「鋼珠會想從哪裡滾到哪裡？」
   路沿著山脊走、鑽過拱門、繞著樹幹盤上去、從瀑布後面穿過、貼著城牆外側翻到另一面。
   **軌道要嵌進景裡**（穿過、繞過、從裡面出來），皮膚跟著它經過的地方換（石板路進城、吊橋過峽谷、黃銅軌進鐘樓）。
5. **分成關卡**：把路分成幾條有名字、有性格的路線，每條有自己的主題、主要零件、主要機關和一個記憶點。
   路線之間用站台、落點、機關互相接通，形成很多種走法。
6. **機關與活的東西**：在故事說得通的地方放（鐘樓裡的齒輪、磨坊的水車、碼頭的升降梯）。
7. **光**：關燈之後這顆球靠什麼發光？發光的東西引導視線到下一個目標。
8. **驗證、看畫面、對照下面的數字**，然後修。

## 這是一顆會轉的球：每個朝向都是一個世界

球可以整顆轉，所以「上面」不只一個。**不要只做一個方向。** 使用者明確要求過：只有一個朝上方向的球等於浪費了這個遊戲最特別的地方。

- 一顆球至少要有**兩三個朝向不同的世界**，各有自己的主題和地標，轉過去就是另一幅畫面。例如：
  上面是雪山小鎮，翻過來底下是倒掛的星空港口；側面一整面是長在牆上的森林；天頂垂下一座倒過來的城。
- **顛倒與對照**是好用的手法：同一個東西的倒影版本（白天／夜晚、夏天／冬天、地上／地下）、
  從上面垂下來的建築、根朝天的樹、往上流的瀑布。重用素材時換配色、倒掛、縮放。
- 每個朝向都要**單獨好看**（把球轉到那一面當正面，從球外看一次），而且從任何角度看整顆球都不亂：
  用共同的色調、同一條穿過去的主軌道、或一個橫跨兩個世界的大地標把它們接起來。
- 鋼珠要**真的走得到**：路線靠爬牆、扭轉、翻面、落下，從一個世界進到另一個；不是只有景觀轉過去而已。
- 不同朝向的世界在交界處要處理：誰的東西伸到誰那邊、哪裡是看得穿的縫，不能互相穿模或擠成一團。

## 用上整顆球（可以量的）

`node scripts/globe-report.mjs <id>` 會印出這些數字，沒達標的前面有 `!`。新球交付時應該沒有 `!`，有的話要說明原因。

| 項目 | 目標 | 為什麼 |
|---|---|---|
| 軌道總長 | 球直徑的 **12 倍以上**（真正的 Perplexus 約 29 倍） | 目前的球是 6.6～10.3 倍，都還不夠 |
| 體積 | 球切成 16 格（8 個象限 × 內外兩層），**至少 12 格有軌道，沒有任何一格是空的** | 不留次等區域、不留空洞 |
| 朝向 | **15% 以上的軌道不在「地板」上**（牆、天頂、倒掛）；景觀至少朝 **3 個明顯不同的方向**立著 | 不然只是一張桌子 |
| 佈局 | 站台落在軸線上的、互為鏡像的，各 **不超過 2 個** | 這是公式化最明顯的痕跡 |
| 選擇 | 單一出入口的站台不超過四分之一；要有 3 條路以上的岔口 | 很多種走法 |
| 機關 | 會動的 **4 個以上**，至少 1 個是靠鋼珠重量或重力動的（鉸接） | Perplexus 的靈魂 |
| 發光 | 沒有「自己補的燈疊在共用發光素材上」 | 同一個素材在每顆球要一樣亮 |

數字達標不等於好看好玩，它只是擋住最常見的偷懶。

## 軌道：像 Perplexus 的關卡

- **每條路線混用不同零件**（坡、彎、爬牆、扭轉、螺旋、階梯、釘陣、搓板、平衡木、蛇行、谷、之字坡、半管、V 槽、鐵絲籠……），不要連續好幾段都是同一種。
- **每條路線有自己的皮膚和表面**，而且跟它經過的地方有關。冰面、絨布、橡膠這些不同物理特性的表面要用在說得通的地方。
- **迴圈與捷徑**：路線互相接通；死路要有理由（一盞燈、一個景點），並且容易回頭。
- **可以掉下去的地方**：放手會落到某個有意思的地方（彈跳鼓、漏斗、下一層的站台），不是只有玻璃。
- **難度偏低**：護欄預設略高於半顆球；需要精準停球或抓時機才能過的地方不要做。鋼珠應該大致能靠自己通過。
- **回正規則跟著零件走**：手感怪先檢查零件用得對不對，不要改全域邏輯。
- **支架要少**：軌道掛在景和站台之間。肋條不可以穿過別的軌道（往玻璃拉之前先檢查）。
- **燈和裝飾不能擋住進出口**：往站台邊上擺東西之前，先看那個方向有沒有軌道進出；會垂到下面的東西（浮岩的根）要檢查下方有沒有軌道。

## 每個區域都是同一個水準

- **沒有次等區域。** 底面、背面、高處要和主舞台同樣用心：有主角、有構圖、有光、有足夠的軌道。
- 每個區域要回答得出：主角是什麼？從哪裡看最好看？玩家在這裡能做什麼？
- 裝飾要有構圖：成群、成列、沿著路、圍著主角、留出空白。**不可以用亂數均勻撒滿。**
- 優先重用並改造現有資產（換配色、縮放、倒掛、組合）。

## 不影響別的球、不影響遊戲本身

- 一顆球 = `src/globes/<id>.js`（加上需要時的 `src/globes/<id>/` 資料夾）＋ `src/globes/index.js` 裡的一行。刪掉這些，這顆球就完全卸下。
- **球只能用共用庫，不能改共用庫裡既有的東西。** 既有零件、斷面、表面、皮膚、機關、素材的行為與數字不能動（那會改到別的球）。
- **可以往共用庫加新東西**，條件是：只新增、不覆蓋既有名稱；物理數字寫在庫裡（不寫在球裡）；有跑過台架測試；加完之後架上每一顆球重新驗證一次。
  只有這一顆球用得到、別的球不會用的東西，留在這顆球自己的資料夾，不要進共用庫。
- 引擎（`physics.js`、`main.js`、`input.js`、`render.js` 的流程）不因為某一顆球的需要而改。
- 這顆球自己加的光（`light()`）只能用在這顆球自己的造型上（岩漿、洞穴）；共用素材的光由素材目錄決定。

## 球外的房間

- 整體偏暗，讓光影好看：檯燈的光池、窗光、小燈串、燭光是亮點，其他地方沉下去。
- 不同材質要有不同的質感：木頭有紋理、金屬會反光、布料是霧的、陶瓷有釉、紙是乾的、橡膠墊完全不反光。
- 房間是共用的。為某一顆球調整房間時，要確認其他球放上去也好看。

## 交付前

1. `node scripts/verify.mjs <id>` 通過，沒有新的 `WARNING`。沒動到的球不用重跑，除非共用層有改動。
2. `node scripts/globe-report.mjs <id>` 沒有 `!`，或逐項說明。
3. 動過機關或表面：`node scripts/sim-mechanisms.mjs` 通過。
4. `npx vite build` 成功；`node scripts/asset-report.mjs` 的數字在預算內。
5. 照 [review-loop.md](review-loop.md) 實際看過畫面：球外三個角度、每個區域的球內視角、關燈之後、這顆球最不顯眼的那個區域。
6. 資產庫（`assets/library.json`）已更新。
7. 回報時誠實列出：哪裡還單薄、哪裡沒辦法實際看、哪裡的手感沒有真人試過。
