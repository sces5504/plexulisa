# 渲染檢查與改進

每次改完場景都要實際看畫面。「程式跑得過」不等於「畫面是好的」。
看完一定要寫出具體的批評和下一步；找不到任何問題通常代表看得不夠仔細。

## 怎麼看

### 遊戲內（最終依據）

開發伺服器用 `.claude/launch.json` 的 `plexulisa` 設定啟動，網址加上 `?nosave` 才不會動到使用者的進度；`&globe=<id>` 指定要看哪一顆球。
瀏覽器面板被收起來時截不到圖：請使用者打開面板，或明講這次沒辦法看畫面，不要假裝看過。
頁面上有除錯用的 `window.plex`：

| 用法 | 作用 |
|---|---|
| `plex.start()` | 關掉標題畫面並開始模擬 |
| `plex.setMode('inside' \| 'outside')` | 切換球內／球外視角 |
| `plex.respawn(i)` | 把鋼珠放到第 `i` 盞燈（`plex.world.lanterns` 可查名稱） |
| `plex.cam.yaw`、`pitch`、`wantDist` | 球內鏡頭的方向與距離 |
| `plex.cam.oYaw`、`oPitch`、`outDist` | 球外鏡頭 |
| `plex.world.pads`、`plex.world.routes` | 圓台與軌道資料，用來找拍攝位置 |

切換視角或傳送後等兩三秒再截圖，鏡頭和淡入需要時間。
使用者可能同時在玩同一個分頁，截到奇怪的畫面時先確認是不是被操作過。

### Blender（做資產時）

`mcp__blender__look` 的 `angles` 模式從多個方向看單一資產；需要看材質時用 `material` 著色。
這只能確認資產本身，不能代替遊戲內的檢查，因為燈光、霧、景深和後製都在遊戲裡。

## 固定要看的畫面

1. **球外主視角**：預設的球外鏡頭。整顆球的輪廓、層次、和書桌的關係。
2. **球外另外兩個方向**：轉 `oYaw` 到左右各約 60°，再看一次低角度（`oPitch` 接近 0）。確認沒有哪一面是空的或亂的。
3. **球內每一盞燈**：逐一 `respawn`，各轉兩三個方向。這是玩家實際停留的地方。
4. **沿著軌道**：挑這次改動附近的軌道，把鏡頭放在行進方向上，確認軌道沒有被景觀遮住或吃掉。
5. **特殊朝向**：改到天頂、側牆或海底時，要在那個朝向下看，不能只從正立的角度判斷。

## 檢查項目

對每張畫面逐項回答，寫下看到的事實而不是印象：

- **構圖**：視線先落在哪裡？有沒有近、中、遠三層？主角是誰？有沒有擠成一團或空一大片？
- **輪廓**：新東西的剪影從這個角度認得出來嗎？有沒有和旁邊的東西糊在一起？
- **材質**：和周圍一致嗎？有沒有太亮、太髒、太寫實、太塑膠？倒角和細節在這個距離看得到嗎？
- **燈光**：陰影方向合理嗎？有沒有該亮的地方是黑的（特別是海之下、島的背光面）？發光物有沒有把視線帶到對的地方？
- **細節**：近看有東西可看嗎？有沒有穿模、懸空、閃爍（共面）、破面？
- **軌道可見性**：軌道面、護欄、鋼珠是否一眼可辨？下一段路往哪走看得出來嗎？有沒有東西擋住鏡頭到鋼珠的視線？
- **可玩性**：新放的東西有沒有擋住出入口、燈、升降梯、井？鋼珠碰到它的反應合理嗎？
- **效能**：`asset-report.mjs` 的數字在預算內嗎？幀率有沒有明顯下降？

## 回報格式

- 看了哪些畫面（以及哪些沒辦法看、為什麼）。
- 每個問題一句話：在哪裡、是什麼、打算怎麼改。
- 依影響排序，標出這一輪就該修的，和可以留到下次的。
- 這一輪就該修的，修完再看一次，直到剩下的都是可以留到下次的。
